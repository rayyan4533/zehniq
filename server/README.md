# server

## Backend API wiring

All workspace endpoints below require a Better Auth session cookie. Paths are
relative to `/api/workspaces/:workspaceId`:

- `POST /chat`: stream an answer using AI SDK UI message format. Supply `messages`
  and optionally `conversationId`, `model`, and `webSearch`. The response exposes
  `X-Conversation-Id` through CORS. Only user/assistant history is accepted, and
  the last message must contain user text.
- `GET /conversations`: list conversations.
- `POST /conversations`: create a conversation with an optional JSON `title`.
- `GET /conversations/:conversationId/messages`: load persisted messages.
- `DELETE /conversations/:conversationId`: remove a conversation and its messages.
- `GET /artifacts`: list generated artifacts.
- `POST /artifacts`: enqueue generation with a required `type` and optional
  `title` and `sourceIds`.
- `GET /artifacts/:artifactId`: fetch content/status; poll until READY or FAILED.
- `DELETE /artifacts/:artifactId`: remove an artifact.
- `POST /sources/:sourceId/retry`: enqueue a FAILED source again; returns 202.
  Other states return 409. Source deletion removes its Pinecone vectors first.

Example chat body:

```json
{
  "messages": [
    { "id": "m1", "role": "user", "parts": [{ "type": "text", "text": "Explain my notes" }] }
  ],
  "webSearch": false
}
```

Example artifact body:

```json
{ "type": "FLASHCARDS", "sourceIds": ["source-id"] }
```

### Running background work

`/api/inngest` registers source processing, conversation summarization, and
artifact generation. Start `pnpm dev` from `server/`, set `INNGEST_DEV=1` in
`server/.env`, and start the Inngest development server in another terminal:

```powershell
pnpm dlx inngest-cli@latest dev -u http://localhost:8081/api/inngest
```

For hosted Inngest, unset `INNGEST_DEV` and configure `INNGEST_EVENT_KEY` and
`INNGEST_SIGNING_KEY`. Database tables and relevant provider credentials must
already be configured. This wiring does not apply database migrations.

Run HTTP wiring checks without provider calls using:

```powershell
node --import tsx --test scripts/backend-wiring.test.mjs
```

These tests mock services/session lookup and block database connections; they
verify routing and request handling rather than live model generation.

Generated by `prisma orm init` with the Minimal template.

Use Node.js 24 LTS (the installed Prisma CLI requires at least Node.js 22.18).

## First run

1. Copy `.env.example` to `.env` and set `DATABASE_URL`, `BETTER_AUTH_SECRET`, and `BETTER_AUTH_URL`.
2. Run `pnpm install` and `pnpm contract:emit`.
3. Run `pnpm dev`; the Express API listens on port 8081 unless `PORT` overrides it.
4. Check `/health` and `/api/auth/ok` on that server.

Better Auth uses `pg.Pool` for its PostgreSQL tables. Application queries use the Prisma 8 client in `src/prisma/db.ts`. If the auth tables are not already in the database, create them with the Better Auth CLI migration before signing in.

## Mem0 Platform user memory

The `mem0ai` SDK uses the hosted Mem0 Platform. Add your project API key to
`server/.env` as `MEM0_API_KEY=...` (get it from https://app.mem0.ai), then run
`pnpm check:mem0` from `server/`. This read-only check validates access without
creating or changing memories. Restart the server after changing the key.

Authenticated memory endpoints are mounted at `/api/memory`:
- `GET /` lists the current user's memories (first 100).
- `POST /` accepts `{ "memory": "I prefer short examples." }` and stores a manual memory.
- `PATCH /:memoryId` accepts the same body and updates an owned memory.
- `DELETE /:memoryId` deletes an owned memory.

The chat service searches memories with the authenticated user ID before answering
and sends completed exchanges to Mem0 for automatic extraction. This sends chat
content to Mem0. Inferred memories may take time to become searchable. With no key,
chat memory search and automatic extraction are skipped. The chat service still
needs a chat route/controller before it can be called over HTTP.
